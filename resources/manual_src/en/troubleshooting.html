When an error appears

When an operation fails, a red message appears at the top right of the screen. Errors do not disappear on their own — close them with the × at the top right. If the same error happens repeatedly it is collapsed into one card with a count such as “×3”. Success notices (black) disappear after a few seconds. Yellow cards mean “the operation succeeded, but there is something you should check”; they also stay until closed.

Reading the message

Part Description
First line (bold) What failed (e.g. “Failed to add memo”)
Second line What to try next. When the cause is known the advice matches it; otherwise it is the general advice for that kind of error
Bottom line (code) The error code (a number starting with ERR) and the cause classification (e.g. db_busy). Quoting these when you ask for help speeds up diagnosis
Copy button Copies the code, cause, message, time and page path to the clipboard. Paste it when reporting the problem

When nothing appears

If pressing a button does nothing, reload the page. Unexpected errors inside the app are now also shown at the top right. If the problem persists, the server's gkill_error.log keeps a line for the time of the failure.

When filtering by time of day always gives 0 results

On a smartphone (Android) or a server you started yourself, a search can return 0 results only when a time-of-day filter is set. This happens when the server cannot read the device's time zone; your records are not gone.

  • In the smartphone app, quit the app and start it again.
  • If you start the server yourself, set the TZ environment variable (for example TZ=JST-9) before starting it.
  • If the server's gkill_error.log has a line starting with "sqlite localtime differs", this is the cause.

When the smartphone (Android) app does not start / stays on the "Allow" screen

The smartphone (Android) app stores your records in shared storage at /sdcard/gkill. For that reason the server does not start until you grant "All files access" (on Android 10 and earlier, storage access). If you come back without granting it, the screen keeps showing the message that gkill starts once file access is allowed, together with the "許可する" (Allow) button. Your records are not gone.

  • On Android 11 and later, pressing "許可する" (Allow) opens the Android permission screen. Turn on "All files access" for gkill and return to the app; it then starts automatically.
  • On Android 10 and earlier, pressing "許可する" (Allow) shows a confirmation asking for the permission. Choose "Allow" and the app starts automatically.
  • On Android 10 and earlier, if you refused with "Don't ask again" selected in that confirmation, pressing "許可する" (Allow) shows nothing. Allow access to storage (files) under Android Settings → Apps → gkill → Permissions, then return to the app.
  • The permission screen (on Android 10 and earlier, the confirmation) appears by itself only once, when the app starts. Going back to the home screen and reopening the app does not show it again by itself. If you closed it, open it again from the "許可する" (Allow) button on the screen.
  • If the app still does not start after granting access, quit the app and start it again.
  • If the message "以前の版のデータを /sdcard/gkill へ複製できなかったため、起動を止めました" (startup was stopped because the data from the previous version could not be copied to /sdcard/gkill) appears, your earlier records are still inside the app. This message appears only after updating from a version that kept its data inside the app (1.1.7 to 1.1.9). Check the device's free space and that there is no file (as opposed to a folder) named gkill in /sdcard, then start the app again.
  • When you update from one of versions 1.1.7 to 1.1.9 and /sdcard/gkill already has contents (for example, old data left by version 1.1.6 or earlier), the app starts with that data instead of the records it kept inside the app. The records inside the app are not deleted: quit the app, rename /sdcard/gkill (to set it aside) and start the app again; the records inside the app are then copied to /sdcard/gkill and used.
