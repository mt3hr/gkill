Plugins

With a plugin installed, records left in services other than gkill appear in the same list as your gkill records. It is meant to let you look back on "what was I doing that day" in one place.

Available plugins

Six plugins are provided as standard.

Plugin What it imports
ChatGPT Conversation history exported from ChatGPT
Claude.ai Conversation history exported from Claude.ai
ClaudeCode Chat logs from Claude Code
Codex Work logs from the Codex CLI
Fitbit Health data from Google Takeout (steps, heart rate, calories burned and so on, summarised into one number per day)
GoogleLocation Location history from Google Takeout (shown on the map; no records are created)
Tip: These names are also used when you narrow records by storage in the sidebar of the record list. To see only plugin records, filter by these names.

How to install

Installing a plugin means putting files in place. Follow the steps in order.

  1. Put the plugin executable in the plugins folder inside the gkill home folder. The exact place is a folder named after your user ID, then a folder named after the plugin, both created under plugins.
  2. Start gkill. The first time the plugin is loaded, a settings file named config.json is created automatically in the same folder.
  3. Open config.json in a text editor and write the folder that holds the data you want to import into source_dirs.
  4. Search in the Life Log View and the records appear in the list just like any other record.
Tip: If config.json already exists, gkill never overwrites it. Your settings will not be lost when you edit them.

How to write the source folder

You can write either a folder path or a file path in source_dirs. The rules are as follows.

Notation Meaning
A path starting with ~ A location relative to your own home folder
* ** ? [] Treats part of a folder or file name as "anything"
When you give a folder It searches down through the sub-folders to find the target files
When you give a file directly It reads the contents of that file as-is
When you leave it empty ChatGPT and Claude.ai look in the plugin folder; ClaudeCode and Codex each look where their CLI stores its logs by default

When you import data from Google Takeout

For health data and location history, leave the ZIP file you downloaded from Google Takeout as it is and just put it in a folder. Folders you have unzipped yourself are not read.

In source_dirs, write the folder that holds the ZIP file. You may also write the path of the ZIP file itself.

How you place the files What happens
Several split ZIP files side by side in one folder They are read together as a single download
A newer download placed in a separate folder Where the dates overlap, only the newer one is used. Periods that exist only in the older one are kept
Tip: You do not need to delete older downloads. Even when the dates overlap, values such as step counts are never counted twice.
Tip: Entries in config.json that start with _ (an underscore) are only there to explain the format. You may delete them.
Tip: You do not need to restart gkill after editing config.json. The new settings are used from your next search onward.

What you can and cannot do

Records imported by a plugin are read-only. gkill cannot change them, so that your original data stays intact.

Operation Available?
Add Tag / Add tag from history Yes
Add Text Yes
Add Notification Yes
Repost Yes
Make Task Yes
Copy content / Copy ID Yes
Edit No (not shown in the menu)
Delete No (not shown in the menu)
Tip: If you tag the imported conversations, you can find them later with the tag filter in the Life Log View.

Importing everything again

What a plugin imports is kept on disk to make display fast. If you have replaced a large part of the source and want everything read again, stop gkill and run the following command.

gkill_server clear_cache plugin YOUR_USER_ID

The next time you start gkill and search, the data is read from the source again.

When nothing shows up

Symptom What to check
No records at all Check that the source files really exist in the folder you wrote in source_dirs. A typo in the path is the most common cause.
The settings file is not created Check that the executable is in the right place. The folder names are your user ID, then the plugin name, in that order.
The content stays old Import everything again with the procedure above.
"Failed to fetch plugin content" is displayed The plugin executable may not be starting. Check that it is not damaged and that you have permission to run it.
Tip: Long-press (mobile) or right-click (desktop) a record and choose "Plugin Settings" to open that plugin's settings screen. You can change and save the source folders there. Editing config.json in the plugin folder directly still works too.
