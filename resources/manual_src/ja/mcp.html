AI連携

Claude などの AI アシスタントと gkill を連携することで、会話形式でライフログを検索・追加・編集できるようになります。

できること

操作例
記録の検索「先週のランチ記録を見せて」「今月の支出を集計して」
記録の追加「今日のメモを追加して」「タスクを作って」
記録の更新・削除「このタスクを完了にして」
GPS・ファイルの取得「今日の移動経路を教えて」
設定の確認「テンプレート一覧を見せて」
運用メモの参照設定画面でタグ・記録保管場所・板・テンプレートに書いた「説明」を先に読み、あなたの使い方に沿って記録を探します
使い方の自習検索条件やページ送りの決まりを、AIが「ヘルプ」機能で自分で調べます。うまく探せないときは「gkillのヘルプで調べて」と頼めます
スキルの利用設定画面で登録した手順書（スキル）を AI が読み、書かれた手順どおりに作業します。AI にスキルを作らせたり直させたりもできます

連携の種類

種類できること起動コマンドツール数HTTP時のポート
読み取り専用記録の閲覧・検索のみ。追加・変更はできないgkill_server mcp --kind read148808
書き込み専用記録の追加・更新・削除。あわせて記録保管場所名・タグ名・板名の取得もできるgkill_server mcp --kind write338809
読み書き両用閲覧・追加・更新・削除のすべてgkill_server mcp --kind readwrite378810

MCP サーバは gkill_server の一部で、gkill_server mcp --kind <種類> で起動します（gkill_server 本体が起動している必要があります）。接続先や資格情報は環境変数のほか、初回起動時に自動生成される設定ファイル configs/gkill_mcp.json でも指定できます。ログは logs/gkill_mcp_<種類>.log（レベル別ファイルも同じ接頭辞）に出ます。

どの種類でも、プラグインの一覧を取得するツールが1つ含まれます。プラグインで取り込んだ記録の本文は、検索結果にそのまま含めて受け取れます。

スキル

スキルは、AI に渡しておく手順書です（例: 週次のまとめの作り方、ある種類の記録に付けるタグ）。利用者ごとに保存され、どの AI アシスタントから接続しても同じスキルを使えます。AI は作業の前にスキルの一覧を確認し、内容の合うスキルを読んでから作業します。

スキルは1つのフォルダで、先頭に SKILL.md を置きます。SKILL.md の最初に次の形で名前と説明を書き、その後ろに手順を書きます。参考資料・スクリプト・素材などのファイルを同じフォルダに入れることもできます。

---
name: weekly-summary
description: 週次のまとめを作るときの手順
---
# 手順
1. ...
操作方法
追加・置き換え設定画面の「スキル」で、フォルダを zip にしてアップロードします。追加・削除・変更されるファイルを確認してから「適用」を押すと、同じ名前のスキルは丸ごと置き換わります。
中身の確認・持ち出し「表示」で各ファイルの中身を見られます。「ダウンロード」で zip として保存でき、手元で直してそのままアップロードし直せます。
削除設定画面の「スキル」の「削除」で、スキルを丸ごと消します。
AI による作成・修正書き込みできる連携では、AI がスキルを作ったり、ファイルを書き換えたりできます。AI はスキルを削除できません。
ヒント: スキルの変更はすぐに反映され、変更の履歴は残りません。AI に直させる前に、必要なら「ダウンロード」で控えを取ってください。名前に使えるのは英小文字・数字・ハイフン（64文字まで）、ファイル名に使えるのは英数字と ._- だけです。スクリプトは gkill では実行されません。

ファイルの受け渡し

ファイル記録（画像・動画・ドキュメント）をAIに見せる方法は、接続形態に応じて自動的に切り替わります。

接続形態受け渡し方法
ローカル接続（同じPC上のAI）ファイルの保存場所（実パス）がAIに渡され、AIがファイルを直接読み取れます。
リモート接続（インターネット経由のAI）有効期限付きの専用URLが発行され、AIはそのURLからファイルを取得します。画像はサムネイルと原寸の両方が渡されます。gkill本体を公開する必要はありません。
ヒント: 埋め込み転送のサイズ上限（既定8MB）は環境変数 GKILL_MCP_MAX_FILE_BYTES、URLの有効期限（既定1時間）は GKILL_MCP_FILE_LINK_TTL_MS で調整できます。

設定方法（Claude Desktop）

Claude Desktop の設定ファイル（claude_desktop_config.json）に以下を追記します。

読み取り専用で連携する場合

{
  "mcpServers": {
    "gkill": {
      "command": "gkill_server",
      "args": ["mcp", "--kind", "read"],
      "env": {
        "GKILL_BASE_URL": "http://localhost:9999",
        "GKILL_USER": "あなたのユーザーID",
        "GKILL_PASSWORD_SHA256": "パスワードのSHA256ハッシュ"
      }
    }
  }
}
ヒント: GKILL_PASSWORD_SHA256 はパスワードをSHA256でハッシュ化した値です。コマンドプロンプト（Windows）で certutil -hashfile - SHA256 などのツールで生成できます。

設定方法（Claude Code）

ターミナルで以下のコマンドを実行します。

# 読み取り専用で追加（環境変数は -- の前、実行コマンドは -- の後ろに書きます）
claude mcp add gkill \
  --env GKILL_BASE_URL=http://localhost:9999 \
  --env GKILL_USER=ユーザーID \
  --env GKILL_PASSWORD_SHA256=ハッシュ値 \
  -- gkill_server mcp --kind read
ヒント: gkill_server は PATH に通っている前提です（通っていなければフルパスを書きます）。種類を変えたいときは --kind を write か readwrite に変えます。

リモートから使う（HTTP接続）

AIが同じPCにいない場合は、MCPサーバ自体をHTTPで待ち受けさせ、インターネット経由のAIから接続できます。この方式では接続時にOAuthによる認可が行われるため、gkill本体をインターネットに公開する必要はありません。

認可は接続の種類（読み取り専用・書き込み用・読み書き両用）ごとに行われます。読み取り専用として認可した接続をそのまま書き込みに使うことはできません。種類を変えたときや、それまで使えていた接続が「権限が足りない」という理由で失敗するようになったときは、AI側でいったん接続を解除し、認可をやり直してください。

# 読み書き両用をHTTPで待ち受ける例
MCP_PORT=8810 MCP_OAUTH_ISSUER=https://example.com \
GKILL_BASE_URL=http://localhost:9999 \
GKILL_USER=ユーザーID \
GKILL_PASSWORD_SHA256=ハッシュ値 \
gkill_server mcp --kind readwrite --transport http
ヒント: gkillサーバ自体をインターネットに公開して使うこともできます。その場合は GKILL_BASE_URL に公開アドレスを指定し、サーバ設定でTLS（HTTPS）を有効にしてください。
