AI 연동

Claude 등의 AI 어시스턴트와 gkill을 연동하면 자연어 대화로 라이프로그를 검색·추가·편집할 수 있습니다.

할 수 있는 것

작업예시
기록 검색"지난주 점심 메모 보여줘" / "이번 달 지출 정리해줘"
기록 추가"오늘 메모 추가해줘" / "할 일 만들어줘"
기록 수정 / 삭제"이 할 일 완료로 표시해줘"
GPS / 파일 가져오기"오늘 이동 경로 보여줘"
설정 확인"템플릿 목록 보여줘"
운용 메모 참조설정 화면에서 태그·저장 위치·보드·템플릿에 적은 "설명"을 먼저 읽고, 사용자의 사용 방식에 맞게 기록을 찾습니다
사용법 자습검색 조건이나 페이지 넘김 규칙을 AI가 「도움말」 기능으로 스스로 조사합니다. 잘 찾지 못할 때는 「gkill 도움말에서 찾아봐」라고 부탁할 수 있습니다
스킬 활용설정 화면에 등록한 작업 절차서(스킬)를 AI가 읽고, 적힌 절차대로 작업합니다. AI에게 스킬을 만들거나 고치게 할 수도 있습니다

연동 유형

유형할 수 있는 일실행 명령도구 수HTTP 시 포트
읽기 전용기록 조회·검색만 가능. 추가·변경은 불가gkill_server mcp --kind read148808
쓰기 전용기록 추가·수정·삭제. 아울러 저장소 이름·태그 이름·보드 이름 조회도 가능gkill_server mcp --kind write338809
읽기 및 쓰기조회·추가·수정·삭제 모두 가능gkill_server mcp --kind readwrite378810

MCP 서버는 gkill_server 의 일부이며 gkill_server mcp --kind <유형> 으로 실행합니다(gkill_server 본체가 실행 중이어야 합니다). 접속 대상과 자격 증명은 환경 변수 외에, 처음 실행할 때 자동 생성되는 설정 파일 configs/gkill_mcp.json 으로도 지정할 수 있습니다. 로그는 logs/gkill_mcp_<유형>.log(레벨별 파일도 같은 접두사)에 기록됩니다.

어떤 유형이든 플러그인 목록을 가져오는 도구 1개가 포함됩니다. 플러그인으로 가져온 기록의 본문은 검색 결과에 그대로 포함해서 받을 수 있습니다.

스킬

스킬은 AI에 미리 전달해 두는 작업 절차서입니다(예: 주간 정리를 만드는 방법, 특정 종류의 기록에 붙일 태그). 사용자별로 저장되며, 어느 AI 어시스턴트로 연결하든 같은 스킬을 사용합니다. AI는 작업 전에 스킬 목록을 확인하고, 내용이 맞는 스킬을 읽은 뒤 작업합니다.

스킬은 하나의 폴더이며, 맨 위에 SKILL.md를 둡니다. SKILL.md의 첫머리에 아래 형식으로 이름과 설명을 쓰고, 그 뒤에 절차를 씁니다. 같은 폴더에 참고 자료·스크립트·소재 등의 파일을 넣을 수도 있습니다.

---
name: weekly-summary
description: 주간 정리를 만드는 절차
---
# 절차
1. ...
작업방법
추가·교체설정 화면의 "스킬"에서 폴더를 zip으로 묶어 업로드합니다. 추가·삭제·변경될 파일을 확인한 뒤 "적용"을 누르면 같은 이름의 스킬이 통째로 교체됩니다.
내용 확인·내보내기"보기"로 각 파일의 내용을 볼 수 있습니다. "다운로드"로 zip으로 저장해, 로컬에서 고친 뒤 그대로 다시 업로드할 수 있습니다.
삭제설정 화면 "스킬"의 "삭제"로 스킬을 통째로 지웁니다.
AI에 의한 작성·수정쓰기가 가능한 연동에서는 AI가 스킬을 만들거나 파일을 고쳐 쓸 수 있습니다. AI는 스킬을 삭제할 수 없습니다.
팁: 스킬의 변경은 즉시 반영되며 변경 이력은 남지 않습니다. AI에게 고치게 하기 전에 필요하면 "다운로드"로 사본을 받아 두세요. 이름에는 영문 소문자·숫자·하이픈(64자까지), 파일 이름에는 영숫자와 ._-만 쓸 수 있습니다. gkill은 스크립트를 실행하지 않습니다.

파일 전달

파일 기록(이미지·동영상·문서)을 AI에게 보여주는 방법은 연결 형태에 따라 자동으로 전환됩니다.

연결 형태전달 방법
로컬 연결(같은 PC의 AI)파일의 저장 위치(실제 경로)가 AI에 전달되어, AI가 파일을 직접 읽을 수 있습니다.
원격 연결(인터넷 경유의 AI)유효 기간이 있는 전용 URL이 발행되어, AI는 그 URL에서 파일을 가져옵니다. 이미지는 섬네일과 원본 크기 모두 전달됩니다. gkill 본체를 공개할 필요는 없습니다.
팁: 내장 전송의 크기 상한(기본 8MB)은 환경 변수 GKILL_MCP_MAX_FILE_BYTES로, URL 유효 기간(기본 1시간)은 GKILL_MCP_FILE_LINK_TTL_MS로 조정할 수 있습니다.

설정 방법 (Claude Desktop)

Claude Desktop 설정 파일(claude_desktop_config.json)에 다음을 추가합니다.

읽기 전용 연동

{
  "mcpServers": {
    "gkill": {
      "command": "gkill_server",
      "args": ["mcp", "--kind", "read"],
      "env": {
        "GKILL_BASE_URL": "http://localhost:9999",
        "GKILL_USER": "사용자-ID",
        "GKILL_PASSWORD_SHA256": "비밀번호의-SHA256-해시"
      }
    }
  }
}
팁: GKILL_PASSWORD_SHA256은 비밀번호를 SHA256으로 해시한 값입니다. 운영 체제에서 제공하는 도구로 생성할 수 있습니다.

설정 방법 (Claude Code)

claude mcp add gkill \
  --env GKILL_BASE_URL=http://localhost:9999 \
  --env GKILL_USER=사용자-ID \
  --env GKILL_PASSWORD_SHA256=해시값 \
  -- gkill_server mcp --kind read
팁: gkill_server 가 PATH 에 있다고 가정합니다(없으면 전체 경로를 적습니다). 유형을 바꾸려면 --kind 를 write 또는 readwrite 로 바꿉니다.

원격에서 사용하기 (HTTP 연결)

AI가 같은 PC에 없는 경우 MCP 서버 자체를 HTTP로 대기시켜 인터넷을 통한 AI에서 접속할 수 있습니다. 이 방식은 접속 시 OAuth 인가가 이루어지므로 gkill 본체를 인터넷에 공개할 필요가 없습니다.

인가는 연결 종류(읽기 전용·쓰기용·읽고 쓰기용)별로 이루어집니다. 읽기 전용으로 인가한 연결을 그대로 쓰기에 사용할 수는 없습니다. 종류를 바꾸었거나, 이전까지 잘 되던 연결이 권한 부족으로 실패하기 시작하면 AI 측에서 연결을 해제하고 다시 인가해 주세요.

# 읽기 및 쓰기를 HTTP로 대기시키는 예
MCP_PORT=8810 MCP_OAUTH_ISSUER=https://example.com \
GKILL_BASE_URL=http://localhost:9999 \
GKILL_USER=사용자-ID \
GKILL_PASSWORD_SHA256=해시값 \
gkill_server mcp --kind readwrite --transport http
팁: gkill 서버 자체를 인터넷에 공개해 사용할 수도 있습니다. 그 경우 GKILL_BASE_URL에 공개 주소를 지정하고 서버 설정에서 TLS(HTTPS)를 활성화하세요.
