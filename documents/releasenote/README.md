# リリースノート

GitHub のリリースページに掲載した本文を、そのまま保管したもの。
本文には手を入れていない（見出しの表記ゆれも当時のまま）。

まだ GitHub で公開していないものだけは例外で、公開前の下書きを置いてある。
一覧で「GitHub 未公開」と印を付けてあり、公開したら印を外して本文を取り直す。

## ファイル名

```
<タグ>_<公開日(JST)>_<コミットハッシュ先頭8桁>.md
```

- 公開日は GitHub のリリース公開日時を JST に直したもの。**コミット日とは1日ずれることがある**ので、
  タグが指すコミットの日付ではなく公開日を使う
- ハッシュはそのタグが指すコミット。完全な値は下の表に載せてある

> **注意:** ここに記録したハッシュは **2026-10-01 の全履歴書き換え後**のもの
> （書き換えは 2026-08-06・08-24・09-21・09-29・10-01 の5回。それ以前の値はもう存在しない）。
> 再び履歴を書き換えるとすべて無効になるので、そのときはこのフォルダも作り直すこと。
> ファイル名の8桁もハッシュなので、作り直しにはリネームが要る。

## 追加のしかた

リリースを公開してタグを打ったあと、リポジトリのルートで次を実行する。

```bash
TAG=v1.1.7
HASH=$(git rev-list -n 1 "$TAG")
DATE=$(gh release view "$TAG" --json publishedAt --jq '.publishedAt' \
       | xargs -I{} date -u -d "{} +9 hours" +%Y%m%d)
gh release view "$TAG" --json body --jq .body \
  > "documents/releasenote/${TAG}_${DATE}_${HASH:0:8}.md"
```

書き出したあと、上の表にも1行足す。

### 下書きを公開後の名前に直す

公開前に下書きを置いた場合、ファイル名の日付とハッシュは仮のもの（`XXXXXXXX`）になっている。
タグを打って公開したあと、本文はそのままに名前だけ直す。

```bash
TAG=v1.1.7
HASH=$(git rev-list -n 1 "$TAG")
DATE=$(gh release view "$TAG" --json publishedAt --jq '.publishedAt' \
       | xargs -I{} date -u -d "{} +9 hours" +%Y%m%d)
git mv "documents/releasenote/${TAG}_"*"_XXXXXXXX.md" \
       "documents/releasenote/${TAG}_${DATE}_${HASH:0:8}.md"
```

このとき、上の表の「未公開」の印・公開日・コミットも実際の値に直す。
GitHub 側の本文を公開後に手直ししたときは、`gh release view` で取り直して上書きする。
