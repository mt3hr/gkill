# v1.1.11

## ⚠️ 更新するときの注意

- **腕時計（Wear OS）を使っている方**: スマホ側（`gkill_wear_companion`）の APK を入れ直してください。時計から打刻を終了すると、更新者と更新端末が前の版のまま保存される不具合の修正です（下の BugFix）。時計側（`gkill_wear_watch`）に変更はありません。
- **AI連携（MCP）を使っている方**: ツール定義が変わりました（write / readwrite にツールを 8 本追加、`gkill_delete_kyou` の既定を連鎖削除に変更）。AI クライアント側で再接続（ツール一覧の取り直し）をしてください。再接続しなくても既存のツールは使えますが、追加したツールは再接続するまで見えません。**`gkill_delete_kyou` は再接続の有無にかかわらず、この版から既定で、記録に付いているタグ・テキスト・通知と、その記録を参照するリポスト・リポストタスクも一緒に削除します**（1 件だけ消すときは `cascade: false` を指定してください）。
- **Codex のプラグインを使っている方**: プラグインのバイナリを入れ替えてください。入れ替え後の初回起動でキャッシュを作り直します。
- **取り込んだ HTML ファイル**: 開いたときに、HTML の中のスクリプトが動くようになりました（これまでは動かず真っ白でした）。gkill の画面とは別の出所として扱うので、ログインの情報や gkill の画面が保存しているデータには触れられませんが、信頼できない HTML ファイルを取り込んでいる場合は開く前に気を付けてください。

## あっぷでーと

- 記録の連鎖削除（記録と、付いているタグ・テキスト・通知、参照するリポスト・リポストタスクを一緒に消す）を、サーバ側の 1 つの処理にまとめました。画面からは 1 回の要求で済み、AI連携（MCP）の削除も同じ処理を使います。画面から見た削除の動きは変わりません

### プラグイン

- Codex: Codex CLI 0.151 以降のログに対応。これまではチャットの本文が入らず、1 セッションがツール呼び出しだけの 1 件になっていました。Claude.ai のプラグインと同じく 1 メッセージ 1 件にし、返事は最終回答と質問を本文に、途中の報告・思考・ツールの実行・変更したファイルは「作業の経過」に畳みます。選択肢付きの質問は設問と選択肢で表示し、回答は回答の文だけを出します。旧形式のログも引き続き読めます（上の注意のとおり、入れ替え後の初回起動でキャッシュを作り直します）

### 腕時計（Wear OS）

- スマホ側アプリ（`gkill_wear_companion`）の不具合修正のみ（下の BugFix）。時計側アプリに変更はありません

### AI連携（MCP）

- `gkill_upload_files` を追加（write / readwrite）。画面の「アップロード」の「ファイル」タブと同じ引数でファイルを置きます。各ファイルは `file_name` と `data_base64` の組か、`file_path`（stdio で接続したときだけ）で渡します。既定は画面と同じで、ファイルの書き込み先に設定したリポジトリへ置き、同じ名前があれば名前を変えて保存し、関連時刻はファイルの更新日時（取れなければ現在時刻）です
- リポスト・リポストタスク・通知の作成と編集、ファイルの記録の編集のツールを追加: `gkill_add_rekyou` / `gkill_update_rekyou` / `gkill_add_mirekyou` / `gkill_update_mirekyou` / `gkill_add_notification` / `gkill_update_notification` / `gkill_update_idf`（write / readwrite）。作成のツールは、参照先の記録が実在することを確かめてから書きます
- `gkill_delete_kyou` の既定を連鎖削除に（`cascade: false` で 1 件だけ）。応答の `deleted[]` をそのまま `gkill_restore_kyou` の `targets[]` に渡すと、まとめて元に戻せます。ファイルの記録も削除・復元・履歴の対象にしました
- 連鎖削除・ファイルのアップロード・メモ帳（KFTL）の送信で作る記録も、作成・更新の端末の欄を `mcp` にしました（これまではサーバの端末名でした。これより前に書いた記録はそのまま残します）
- ツール一覧（`tools/list`）の転送量が、write / readwrite では追加した 8 本のツールと削除の説明のぶん増えています

## BugFix

- 取り込んだ HTML ファイル（3D ビューアなど、1 ファイルで完結する HTML）を開くと真っ白になる不具合を修正（上の注意を参照）
- ZIP の中身のテキスト表示で、大きなファイルを途中で読み止めた位置が文字の途中だと、全体が文字化けする不具合を修正
- 詳細表示とダイアログで、動画の全体の長さが再生するまで出ない（`0:00` のまま）不具合を修正。一覧の行では従来どおり、再生するまで動画を読み込みません
- 一覧の中のリポスト・リポストタスクで、参照先の記録の画像をサムネイルではなく原寸で読み込んでいた不具合を修正
- ファイルをアップロードした直後や、ファイルの記録の時刻を直した・復元した直後に、その記録が次のキャッシュの更新まで検索に出ないことがある不具合を修正
- リポストを削除しても、キャッシュの作り直し（起動時・リポジトリの読み直しなど）のたびに削除前に戻って見える不具合を修正。あわせて、履歴に削除が出ない・AI連携（MCP）からの復元が効かない・連鎖削除が削除済みのリポストを拾い直す、も直ります
- 通知の履歴に削除した版が出ず、AI連携（MCP）から通知を復元できなかった不具合を修正
- 通知とリポストの作成者と作成端末が、読むたびに入れ替わって返る不具合を修正。編集・削除・復元で、入れ替わった向きのまま新しい版が保存されることがありました（すでに入れ替わって保存された版は書き換えません）
- ファイルの記録を削除するたびに、削除の版の作成者と作成端末が入れ替わって保存される不具合を修正（すでに保存された版は書き換えません）
- Git のコミットログの記録で、作成者・更新者に名前ではなく `{名前 メール 時刻}` の形の文字列が入ることがある不具合を修正
- 通知を配信したときに保存する版で、更新者の欄にプロセス名が入り、更新アプリ・更新端末が前の版のまま残っていた不具合を修正
- ファイルの自動取り込みで作った記録の、更新者と更新端末が逆に入っていた不具合を修正
- 腕時計（Wear OS）で打刻を終了すると、更新者と更新端末が前の版を書いた利用者・端末のまま保存されていた不具合を修正（スマホ側アプリ。利用者 ID と端末名が取れないときは保存せず、時計に設定の取得に失敗した旨を出します）
- サーバを閉じるときに、まれにプロセスごと異常終了することがある不具合を修正（通知の定期更新が、閉じた後の設定を読みに行っていました）

## Other

- 依存ライブラリを更新（Vuetify・Vite・Vue・mermaid・vue-router ほか、Go の SQLite ドライバ・go-git・golang.org/x）。推移依存の脆弱性（katex・source-map-js・shell-quote ほか）を解消し、Go を 1.26.10 に上げて標準ライブラリの脆弱性（net/http・crypto/tls・crypto/x509 ほか）を解消しました。ソースからビルドするには Go 1.26.10 以上が要ります（開発者向け）

- 作成・更新の欄（時刻・アプリ・端末・利用者）を全種類・全層で往復させるテストと、SQL の列の順と読み書きの引数の順の食い違いを落とす検査を追加（開発者向け）
- Nightly の依存の監査で、修正版の無い開発用依存の脆弱性だけを、期限付きで名指しして通せるように（開発者向け）
- コミット時に、実際の環境や記録に由来する値の形を検査する仕組みを追加（その検査を持つ環境だけ。開発者向け）
- バージョンを 1.1.11 に。v1.1.10 のリリースノートを公開後の名前と値に直しました
