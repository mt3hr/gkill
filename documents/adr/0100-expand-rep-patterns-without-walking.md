# ADR-0100: リポジトリ定義のパターン展開は対象ツリーを歩かない

## Context

`GetRepositories` は REPOSITORY テーブルの行ごとに `FILE` 列のパターンを実在パスへ展開する。展開には go-zglob を使っていた。

go-zglob の `Glob` は、マッチしたディレクトリで `filepath.SkipDir` を返さない。さらに枝刈り条件（`len(path) < len(dirmask)`）が root 直下の子に対しては絶対に成立しない。結果として `<静的ディレクトリ>/<接頭辞>*` のような、`**` を1つも含まないパターンでも**対象ツリー全体を無条件に再帰 walk する**。

一方 `*` は go-zglob 内部で正規表現 `[^/]*` に落ちるので `/` をまたげない。つまり **root 直下より深い階層に新しいマッチは原理的に存在しない**。歩いた結果は1件もマッチを増やさないまま捨てられていた。

これはキャッシュ事前生成の CLI だけの問題ではない。展開はリポジトリの構築時に走り、リポジトリはプロセス寿命で保持されて TTL を持たないが、無効化（ログアウト・`POST /api/reload_repositories`）のたびに作り直される。認証つきの59ルートは最初のリクエストでこの構築を待つ。

## Decision

REPOSITORY の `FILE` パターンのうち「`**`・`{`・`!(` を含まない」かつ「`*` が最終セグメントにしか無い」ものは、親ディレクトリを1回列挙して展開する。それ以外は従来どおり go-zglob へ渡す。

環境変数が展開されずにパターンがファイルシステムのルート直下になった場合は、走査せず0件を返して警告する。

## Rejected alternatives

- **go-zglob を fork して `SkipDir` を返すようにする** — 上流の意味論（`**` の扱い、ブレース展開、`(?i:)` の付与）を丸ごと抱え込むことになる。gkill が使っているのは全体のごく一部で、その一部は自前で書いたほうが短い。fork の追随コストに見合わない。

- **パターン記法を「最終セグメントの `*` だけ」に制限し、go-zglob をやめる** — `documents/reverse/dvnf-rep-type-spec.md` が `directory` 型の例として `**` を挙げており、設定画面から任意のパターンを入れられる。記法を狭めると、いま動いている設定が**エラーも出さずに0件**になる。フォールバックの経路は残さなければならない。

- **展開の結果をプロセス内でキャッシュする** — 構築そのものが「rep 定義を読み直す」ためのものなので、キャッシュすると設定変更やファイル追加が反映されなくなる。しかも1回あたりの費用が下がらないので、初回の待ちは変わらない。

- **展開を並列化する** — 総walk量は変わらないので、外付けストレージの帯域と OS のディレクトリキャッシュを食い合うだけ。無駄な走査を消すほうが桁で効く。

- **`filepath.Match` をそのまま使う** — go-zglob は `?` と `[` をメタ文字と見なさない（glob 判定が `"*{"` だけを見る）。`filepath.Match` はどちらもメタ文字として扱うので、`literal[a].db` のようなファイル名を持つ設定の意味が変わる。1セグメントぶんの照合は自前で書く。

## Consequences

- 展開の意味論を2箇所（自前の1セグメント照合と go-zglob）で持つことになる。フォールバックの条件を間違えると、`**` を含む設定が**エラーも出さずに0件**になる。`repFilePatternNeedsWalk` の条件はテストで固定してある。
- 大文字小文字の扱いは go-zglob に揃える（Windows / macOS では無視）。揃えないと、綴りの大小を間違えた設定が**それまで動いていたのに黙って0件**になる。手元の設定で大小の食い違いは1件も無かったが、救済そのものは残す。
- disable 指定の照合（`zglob.Match`）は据え置く。判定対象は展開が返した実在パスなので、展開側だけ変えても集合は変わらない。
- 環境変数が未設定のときの挙動が変わる。従来は `/Archive_*` のようなパターンでドライブ全体を歩いた末に0件を返していた。これを走査せずに0件＋警告にする。

## Evidence

**構造上の背理。** `*` は `[^/]*` に落ちて `/` をまたげないので、最終セグメントにしか `*` が無いパターンでは root 直下より深い階層に新しいマッチが存在しない。歩いた結果は必ず全部捨てられる。

計測でも、数万ディレクトリ規模の置き場では**1パターンあたり秒単位**かかっていた。返るのは数十件で、費用は「返す件数」ではなく「木の大きさ」に比例する。作業用の Git 置き場のように、浅いところに数十個しか無いのに深いところにファイルが多い木がいちばん悪い。数十行の設定を持つ利用者では、この合計が分単位になる。**同じ費用をサムネイル生成と互換動画生成が別々に払っていた。**

置き換え後は、この区間が体感できない程度まで落ちた。

なお、手元の設定と配布サンプルを全数走査した限りでは、`**` / `{a,b}` / `!(...)` / `?` / `[...]` はいずれも使われておらず、`*` が2個以上あるパターンも `*` が最終セグメント以外にあるパターンも無かった。フォールバック経路は「使われていないが許されている」記法のために残してある。
