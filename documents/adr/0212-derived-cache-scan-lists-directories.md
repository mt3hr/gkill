# ADR-0212: 派生キャッシュの一括生成は1件ずつ stat せずディレクトリを列挙する

## Context

サムネイルと互換動画のキャッシュ名にはファイルサイズが入っている（[ADR-0705](0705-per-user-derived-cache-dir.md) のパス構成）。同じパスのファイルが差し替わったときに自動で別エントリにするためで、この設計自体は正しい。

その帰結として、一括生成は「キャッシュがあるか」を判定する前に必ず元ファイルのサイズを知る必要があった。実装は素直に1件ずつ `os.Stat` していた。元ファイルは外付けストレージにあり、キャッシュはローカルにある。つまり判定1件につき2回の stat を、別々のデバイスへ投げていた。

対象は数十万件規模で、これがそのまま待ち時間になっていた。生成すべきものが1件も無い（全部キャッシュ済みの）回でも変わらない。

## Decision

一括生成は、生成対象を親ディレクトリごとにまとめて `os.ReadDir` し、その結果からファイルサイズを得る。キャッシュ側もリポジトリごとに1回 `os.ReadDir` して、ファイル名の集合と突き合わせる。

## Rejected alternatives

- **IDF の索引にファイルサイズ列を足す** — 索引は追加専用で、既存の行にサイズは入っていない。全リポジトリの再索引が要るうえ、ファイルが差し替わったときに索引と実体がずれる（差し替えを検出するためにサイズを使っているのに、そのサイズを索引から取ったら検出できない）。判定の根拠を実体から離してはいけない。

- **キャッシュのファイル名を接頭辞（パスのSHA1）だけで突き合わせ、サイズを見ない** — 元ファイルの stat が消せるので速いが、**差し替わったファイルのサムネイルが古いまま出続ける**。しかも一括生成でしか起きないので、画面で見ているぶんには正しく、原因に辿り着けない。近似で済ませてよい場所ではない。

- **サイドカーの台帳（相対パス→サイズ）を派生キャッシュの隣に置く** — 台帳と実体の同期という新しい壊れ方を増やす。台帳が古いと上と同じ「古いサムネイルが出続ける」になる。ディレクトリ列挙で同じ情報が正確に取れるのだから、持つ必要が無い。

- **stat を並列化するだけで済ませる** — 待ちは減るが総syscall数は変わらず、外付けストレージのキューを埋める。ディレクトリ数はファイル数より3桁少ないので、そもそも投げないほうが効く。

## Consequences

- Windows では `os.ReadDir` が返す `DirEntry.Info()` が追加の syscall を伴わない（列挙時の `FILE_ID_BOTH_DIR_INFO` / `FILE_FULL_DIR_INFO` から `fileStat` を組み立てて返す）ので、サイズは列挙のついでに手に入る。**Linux では `Info()` が lstat へ落ちる**ため、この改善は Windows / macOS でだけ効く。Linux でも従来と同じ回数の syscall にしかならないので悪化はしない。
- 索引に載っているファイル名と実ファイル名の大小が食い違っていると、`os.Stat`（Windows では大小無視）では引けていたものが、列挙結果のマップでは引けなくなる。引けないと**そのファイルのサムネイルだけがエラーも警告も出ないまま作られない**。Windows / macOS では小文字化した鍵での引き直しを入れてある。
- シンボリックリンクは列挙の情報がリンク自身を指すので、実体を `os.Stat` で見に行く必要がある。省くとリンクのサイズでキャッシュ名を作ってしまい、毎回作り直しになる。
- 索引にあって実体の無い行（IDF の索引は追加専用なので必ず出る）は、列挙結果に現れないことで自然に飛ばされる。従来は1件ずつ stat して失敗を見ていた。

## Evidence

判定1件あたりの費用が、判定の材料をどこから取るかで3桁変わる。

| 操作 | 1件あたり |
|---|---|
| 外付けストレージ上のファイルを1件ずつ `os.Stat` | ミリ秒台 |
| ローカルのキャッシュを1件ずつ `os.Stat` | 1ミリ秒弱 |
| 親ディレクトリを `os.ReadDir` して1件ぶんを引く | **マイクロ秒台** |

同じ内容の判定を1万件ぶん行うと、前者は数十秒、後者は数十ミリ秒だった。ファイルは1つのディレクトリに固まっている（リポジトリの大半は生成対象の親ディレクトリが1つだけ）ので、列挙の回数はファイル数ではなくリポジトリ数のオーダーに落ちる。

生成すべきものが1件も無い状態でのサムネイル一括生成は、置き換えで**1桁速くなった**。残っている費用は、リポジトリの構築と、リポジトリごとの索引の読み出しに移っている。
