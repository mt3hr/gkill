# ADR-0060: 綴りは「永続に乗るか」で決める — plaing は凍結、agregate は改名して読み込み互換を残す

## Context

コードベースに綴り誤りに見える識別子が複数ある。**見つけた人は必ず直したくなる**し、実際に何度も提案されている。

しかし綴りの一部は**永続データや外部契約に乗っている**ので、直すと壊れる。どれが直せてどれが直せないかを、その場の勘で判断すると事故になる。

## Decision

判定基準を1つにする。

> **その綴りが「永続データ」または「外部契約」に乗っているか。**

- 乗っている → **凍結する**（製品綴りとして扱い、修正提案をしない）
- 乗っていない → **純粋なリネームで直す**
- 乗っているが直したい → **改名したうえで旧綴りの読み込み互換を残す**

確定した境界（2026-08-05）:

| 綴り | 判定 |
|---|---|
| `plaing` / `Plaing` | **凍結**。5系統に浸透 |
| `agregate` | 改名（`aggregate`）＋ 旧綴りの読み込み互換を残す |
| `identifer` / `extruct` / `ThrusDay` | 純粋なリネームで安全 |

## Rejected alternatives

- **`plaing` を `playing` に直す** — 983箇所・182ファイルに加え、**互換面が5系統**に及ぶ。
  1. `FindQuery` のJSONキーが `share_kyou_info` と `DashboardJSONData` に**永続化**されている
  2. **MCP の外部契約**（ツールスキーマ）
  3. **Wear OS の2APK間プロトコル**（データレイヤーのパス）
  4. **7言語マニュアルのページ名**
  5. `default_page` の**保存値**

  1と5は配布済みのデータ、2と3は配布済みのバイナリ。片方だけ直せない。

- **`agregate` も凍結する** — こちらは型判別文字列だけが永続に乗っていた。改名したうえで**読み込み時に旧綴りも受ける**ようにすれば、書き込みは新綴りに寄せられる。凍結する必要は無かった。

- **移行コードを書いて `plaing` も直す** — 移行できるのは自分のDBの中だけ。MCP のツールスキーマと Wear OS のプロトコルは**相手側の実装**なので、こちらから移行できない。

- **新規コードだけ `playing` にする** — 綴りが2つ並ぶ。検索も置換も効かなくなり、どちらが正しいのか誰にも分からなくなる。

## Consequences

**`plaing` の綴り修正は提案しない。** ルート `/plaing`、`FindQuery` の `plaing_time`、MCP ツールスキーマ、Wear OS のデータレイヤーパス、マニュアルのページ名、`default_page` の保存値は、すべてこの綴りのまま。

**この決定はテストで守られていない。** リネームを防ぐソース走査テストが存在せず、現状は `CLAUDE.md` / `glossary.md` / この ADR という**文書だけが防御線**。一括置換で壊せる状態にある。

新しい綴り誤りを見つけたときは、上の基準（永続データ／外部契約に乗っているか）で判定してから直すこと。
